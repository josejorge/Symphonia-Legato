SymphoniaLegato.Rendering

Operations Guide — shared score-rendering control

System description

ScoreCanvas — the Avalonia control that paints a LayoutResult using DrawingContext directly (no SkiaSharp packages, since Avalonia's own DrawingContext is Skia-backed). Shared between Desktop and Android so both apps render identically. Renders white paper / black ink by deliberate design, independent of the dark app chrome.

Prerequisites

.NET 9 SDK. Depends on SymphoniaLegato.Core, NotationEngine, and LayoutEngine.

Build & verify in isolation

dotnet build src\Core\SymphoniaLegato.Rendering\SymphoniaLegato.Rendering.csproj

No dedicated unit-test project; rendering correctness is verified visually (via the Desktop app) rather than pixel-diffed automatically.

Log files

None — see root operations guide.

Configuration parameters

None of its own — zoom, page size, and theme are all driven by the LayoutResult and app-level theme resources it's handed.

Common troubleshooting

SymptomCause / fix
Score sheet is invisible / looks dark-on-darkDeliberate design: the page is always off-white with near-black ink, independent of the app's dark theme. Don't "theme" it dark to match the menus — that's the exact bug this avoids (see docs/BUGS.md, pitfall #20).
Canvas reports zero size / doesn't scrollMust override MeasureOverride and return a size derived from the LayoutResult — the Render override alone doesn't size the control for the ScrollViewer (pitfall #18).
