SymphoniaLegato.PlaybackEngine

Operations Guide — MIDI playback & metronome

System description

MidiPlaybackEngine plays a Score through the system's MIDI output device via DryWetMidi. ScoreToMidiConverter converts domain ticks (1024/quarter) to MIDI ticks (480 PPQ), emits tempo and a sample-accurate percussion click track. MetronomeEngine is a separate, silent timer used for UI-side beat events.

Prerequisites

.NET 9 SDK. NuGet: Melanchall.DryWetMidi 8.0.0. A reachable MIDI output device at runtime (see root operations guide).

Build & verify in isolation

dotnet build src\Core\SymphoniaLegato.PlaybackEngine\SymphoniaLegato.PlaybackEngine.csproj
dotnet test tests\SymphoniaLegato.PlaybackEngine.Tests --no-build   # 6 tests (ScoreToMidiConverter)

MidiPlaybackEngine itself has no automated tests — it opens a real OS MIDI device, so it needs a fake/abstraction over the device before it's unit-testable (tracked in docs/TODO.md).

Log files

None persisted — logs via ILogger<T>, debug-output only (see root operations guide).

Configuration parameters

MIDI output device selection is configured by the Desktop app's MIDI Settings dialog (not by this library) via IPlaybackEngine.SetOutputDevice(string?) — added 2026-09-15; the selection now persists (Desktop's AppSettingsService) and actually changes which device EnsureOutputDevice() opens (previously hardcoded to OutputDevice.GetByIndex(0) regardless of what was selected — see docs/BUGS.md). SoundFont path is still configured by the same dialog but isn't wired to an actual synth in this library yet.

Common troubleshooting

SymptomCause / fix
A selected MIDI device doesn't produce soundConfirm SetOutputDevice was actually called with that device's name (the Desktop Settings dialog's Apply button does this) — if the name doesn't match any device from OutputDevice.GetAll(), EnsureOutputDevice() falls back to the system default and logs a warning.
Play does nothingThe engine's MIDI snapshot is only rebuilt at the start of playback from the live Score — a caller must not assume the engine already has current data (pitfall #21).
Piano-key preview is silent before the first PlayThe output device opens lazily via EnsureOutputDevice(), shared by both playback and preview — make sure both call sites use it, not just PlayAsync (pitfall #22).
Metronome click doesn't line up / jittersThe audible click comes from a percussion track baked into the MIDI by ScoreToMidiConverter (sample-accurate), not from a UI timer — MetronomeEngine's own Beat event is for UI display only (pitfall #29).
