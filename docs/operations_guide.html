Symphonia Legato — Operations & Maintenance Guide

Cross-platform music notation editor · C# / .NET 9 / Avalonia 11

System description

Symphonia Legato is a desktop music notation editor (Windows/Linux/macOS, Avalonia UI) with a companion Android viewer app. It edits, plays back (MIDI), and exports scores (PDF, PNG, SVG, MusicXML, MIDI, and its own .enscore ZIP format). There is no server component — it is a self-contained desktop application; "operations" here means build, run, and diagnose on a developer or end-user machine, not a hosted service.

Prerequisites

RequirementNotes
.NET SDKglobal.json pins 9.0.0 with rollForward: latestMajor — any installed 9.x or newer SDK works (verified against .NET 10.0.303).
OSWindows, Linux, or macOS for the Desktop app. Android build/deploy needs a machine with the Android SDK reachable by the workload below.
Android workload (optional)dotnet workload install android — a ~1 GB one-time install, required only to build SymphoniaLegato.Android.sln. The main SymphoniaLegato.sln excludes the Android project so Desktop always builds without it.
MIDI output deviceFor audible playback. Windows ships the "Microsoft GS Wavetable Synth" by default; Linux/macOS need a software synth reachable via the OS's MIDI subsystem.

How to build, run, and verify status

# Restore + build Desktop + all tests (0 warnings, 0 errors expected)
dotnet build SymphoniaLegato.sln -c Debug

# Run the desktop app
dotnet run --project src\Apps\SymphoniaLegato.Desktop --no-build

# Run all tests (139 passing as of 2026-09-15)
dotnet test SymphoniaLegato.sln --no-build

# Publish a self-contained Windows EXE
dotnet publish src\Apps\SymphoniaLegato.Desktop -c Release -r win-x64 `
  --self-contained -p:PublishSingleFile=true -o publish\windows

# Android (requires the workload above)
dotnet build SymphoniaLegato.Android.sln -c Debug

Verifying it started correctly: the app has no health-check endpoint (it's a GUI app) — a successful start shows a window titled Untitled • — Symphonia Legato. If the process exits immediately with no window, see Troubleshooting below.

Log files and how to monitor them

There is currently no persistent log file. Program.cs configures logging with AddLogging(b => b.AddDebug().SetMinimumLevel(LogLevel.Debug)) — output only reaches an attached debugger's Output/Debug window (e.g. Visual Studio's Output pane, or dotnet run under a debugger). Nothing is written to disk. If you need to capture logs from an end-user machine without a debugger attached, that's an open gap — see docs/TODO.md.

Common troubleshooting

SymptomLikely cause / fix
Android build fails with a workload errorRun dotnet workload install android, then build SymphoniaLegato.Android.sln specifically (not the main solution).
No sound on PlayOpen MIDI/Audio Settings, pick a device, and click Apply — the selection now persists and actually takes effect (see Configuration above). If the device list is empty, no MIDI output is available on this machine.
AI Assistant panel errors on harmonisation/analysisThe Claude API key wasn't entered (or is invalid) this session. Offline features — chord detection and fingering suggestions — still work with no key.
App crashes immediately at launch with no windowHistorically caused by an invalid Avalonia InputGesture string (fixed in commit 3d64da4 — see docs/BUGS.md). If it recurs, run under a debugger and check the Debug output for an ArgumentException from XAML population.
Build succeeds but Android project is skippedExpected — build SymphoniaLegato.sln for Desktop-only work; use SymphoniaLegato.Android.sln for Android.
